# 小说项目工作流

## 新项目

新建小说时先把未知项分成两类：会显著改变作品方向的关键选择，以及可以在创作中逐步决定的细节。关键选择通常只有题材/核心卖点、目标篇幅、主要 POV、整体基调和明确禁忌；其余内容可先用合理默认值启动。

推荐步骤：

1. 建立 `novel.yaml`，写入题材、受众、POV、时间、文风和节奏参数。
2. 用一句话写故事承诺：主角是谁、想得到什么、最大的阻力是什么、失败意味着什么。
3. 建立主角与 2–5 个最重要角色，先写欲望、恐惧、秘密、关系和可变化点。
4. 建立总纲，只固定关键转折和终局约束，不把每个细节提前锁死。
5. 初始化 `state/state.json`，`current_chapter` 从 0 开始。
6. 写第一章控制卡，再进入正文。

`scripts/init_novel.py` 会从 `assets/templates/` 复制一套最小项目骨架。

## 续写

续写前只读取与当前章节相关的上下文，避免把整本小说重新塞入上下文：

- `novel.yaml`
- `state/state.json`
- 当前卷纲/附近章纲
- 最近 1–3 章正文
- 本章涉及角色的人物卡
- 与本章相关的世界观条目

如果状态与正文冲突，以用户明确说明和已经发表/确认的正文事实为最高依据，修正状态后再续写。

## 章节完成

正文完成后做三层检查：

1. **因果**：本章事件是否由人物选择、外部压力或既有事实推动。
2. **连续性**：时间、地点、物品、伤势、关系、知识边界是否一致。
3. **语言**：句式、对话、描写密度是否符合 `novel.yaml`。

只有在正文稳定后才提交状态事务。事务至少写章节号、摘要，以及本章确实改变的状态；没有变化的字段不要机械重复。
