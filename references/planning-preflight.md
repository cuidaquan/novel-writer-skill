# 写前规划与验收

项目化写作先把题材、读者回报、主角欲望、主要阻力、失败代价、目标规模、POV、文风和结局方向落到文件。已有明确要求时直接采用；其余可以提出合理方案，只有会改变故事方向的选择才需要用户决定。总纲中的“结局状态”可以是方向，不必提前锁死每个情节。

按 [总纲模板](../assets/templates/outline.md) 保留字段标签并填写内容；这些标签供确定性写前检查识别。POV 人物文件至少写明名字、欲望和恐惧。每张准备写的章卡应有具体目标、阻力、至少一项剧情/人物/关系变化和目标字数。字数是规划预算，不代替写作后的正文检查。

## 整本创作

在 `novel.yaml` 写入 `length.target_chapters` 和 `length.target_words`，填完总纲及所有计划章节卡后运行：

```bash
python3 scripts/project_check.py /path/to/novel --preflight book
```

检查会覆盖故事承诺、关键转折、主角弧、类型兑现、每章章卡和视角/资料引用，并确认章卡字数预算至少达到总目标的 90%。修订规模或大纲后重新运行。

## 连载创作

总纲写明故事承诺和结局方向；用 [阶段纲模板](../assets/templates/volume-outline.md) 建立当前卷的 `outline/volumes/volume-01.md`（后续卷按编号递增），写明阶段目标、冲突、阶段末变化和下一阶段压力。准备好下一章章卡后运行：

```bash
python3 scripts/project_check.py /path/to/novel --preflight serial
```

连载只验当前卷与下一章，不要求提前写完整本的章节卡。`build_context.py` 在生成下一章上下文时还会检查总纲、POV 人物与该章章卡；缺项时先修计划再写正文。

写前检查只验证文件和可确定的规划约束。人物动机是否可信、转折是否有力、读者回报是否兑现，仍由写作与审稿环节判断。一次性短篇直接写正文时不需要运行项目写前检查。
